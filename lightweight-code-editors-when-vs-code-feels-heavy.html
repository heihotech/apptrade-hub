Lightweight code editors when VS Code feels heavy

VS Code is genuinely great — but "great" and "right for every situation" aren't the same thing. On an older laptop, a remote server, or when you just want to quickly edit a config file, loading a full Electron app with extensions, language servers, and telemetry can feel like backing a lorry into a parking space. These alternatives won't replace VS Code for every workflow, but for the right person in the right context, they're a genuine upgrade in day-to-day feel.

Why People Look for Something Lighter

The complaints tend to cluster around a few themes: startup time that runs into seconds, RAM usage that climbs past 400–600 MB for a single window, and fan noise on machines that were perfectly quiet before you opened your editor. Sometimes the issue is philosophical — you want a tool that stays out of the way and doesn't try to become an IDE. All of the options below address at least one of these pain points, though none of them are perfect substitutes in every scenario.

Sublime Text — The Classic Contender

Sublime Text has been around since 2008 and remains the editor most people reach for first when leaving VS Code. It opens instantly, handles large files without complaint, and its multi-cursor implementation is still arguably the smoothest of any editor. The Package Control ecosystem covers most language support you'd need.

The honest tradeoff: it's not free. A licence costs $99, though the indefinite free trial (with occasional nag dialogs) is a well-known workaround. If you work in Python or JavaScript daily and want something fast without configuring a terminal-based editor, Sublime Text is the most painless transition from VS Code.

Best for: Developers who want speed and polish and don't mind paying for software.

Helix — A Modern Terminal Editor Worth Your Time

If you're willing to spend a weekend learning something new, Helix is remarkable. It's a terminal-based editor written in Rust with built-in LSP (Language Server Protocol) support, meaning you get real autocompletion and go-to-definition without installing a single plugin. The modal editing is inspired by Vim but with a key difference: selections come before actions, which feels more intuitive once it clicks.

# Install on macOS
brew install helix

# Open a file and check its health
hx --health python

The hx --health command is a small but telling detail — Helix actually tells you which language servers are installed and which are missing. It runs in a terminal, consumes almost no memory, and works over SSH without any setup friction.

Best for: Developers comfortable in the terminal, especially those on remote machines or low-spec hardware.

Zed — Fast, Opinionated, and GPU-Accelerated

Zed is the newest major player here, built by some of the people behind Atom. It's a native app (no Electron) that uses GPU rendering, which makes scrolling through large files feel unusually smooth. Collaboration features are built in at a protocol level rather than bolted on, which is a meaningful difference if you pair program regularly.

The caveats are real though. Zed is macOS and Linux only (Windows support is still in progress at time of writing), the extension ecosystem is thin compared to VS Code, and some settings that VS Code exposes through a UI require editing a JSON config file. It's promising but not yet mature.

Best for: Mac and Linux users who prioritise raw editor performance and occasional pair programming.

Geany — Underrated for Low-End Machines

Geany gets mentioned less often, but it deserves a place on this list. It's a GTK-based editor that runs on Windows, macOS, and Linux, starts in under a second even on old hardware, and has built-in support for compiling and running code in common languages without additional plugins. It won't win design awards, but on a Raspberry Pi or a ten-year-old netbook it's a serious option.

Best for: Users on very limited hardware or those who need a capable editor without any internet connection or package management.

A Quick Comparison

  • Sublime Text — Fast GUI editor, mature ecosystem, paid licence, minimal setup
  • Helix — Terminal-based, zero-config LSP, Rust-powered, steep learning curve
  • Zed — Native GUI, GPU-accelerated, collaborative, Mac/Linux only, young ecosystem
  • Geany — Extremely lightweight GUI, works on ancient hardware, basic but solid

Verdict

There's no single best answer here because the right editor depends heavily on your context. If you're on a capable machine and just find VS Code's startup time annoying, Zed is worth a serious look. If you live in the terminal or work over SSH regularly, invest the time in Helix — it pays off. For something you can hand to anyone and have them productive in five minutes, Sublime Text is still hard to beat. And if your hardware is genuinely old or constrained, don't overlook Geany.

VS Code will still be the right choice for many workflows, particularly anything involving complex debugging or a language with deep IDE-style tooling. But "VS Code or nothing" is a false constraint, and any of these editors will serve you well once you get past the adjustment period.
